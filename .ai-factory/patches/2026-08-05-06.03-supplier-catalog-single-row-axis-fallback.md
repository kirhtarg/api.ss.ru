# Supplier Catalog Single Row Axis Fallback

**Date:** 2026-08-05 06:00
**Files:** app/Services/BikeproductsCatalogService.php, app/Http/Controllers/Admin/BikeproductsCatalogController.php, admin.skateandsnow.ru/components/modules/shop/BikeproductsCatalog.vue
**Severity:** medium

## Problem

Bikeproducts rows whose names do not contain variation values in parentheses could be matched by SKU to a database variation, but the audit showed empty source values for color and size. This made a correctly matched row look confusing and could make it appear as an axis difference.

## Root Cause

The single-product comparison path returned only an SKU comparison for non-variation source rows. It did not include display-only axis comparisons for color and size already present on the matched database variation.

## Solution

For non-variation Bikeproducts source rows matched by SKU, the audit now adds match-status comparisons for existing database color and size axes. These source values are marked as database fallbacks for display. The variation audit cache version was bumped so deployed servers do not reuse stale comparison payloads. The frontend displays the fallback note without changing the raw value used for filtering.

## Prevention

When source rows are intentionally matched by SKU without parsed axes, render database axis fallbacks as informational match comparisons instead of missing source data. Keep cache keys versioned whenever audit payload semantics change.

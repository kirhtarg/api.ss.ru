# Интеграция Ozon Seller API

## Развертывание

1. Развернуть backend и frontend из одной версии репозиториев.
2. Выполнить `php artisan migrate --force` в проекте API.
3. Перезапустить воркеры командой `php artisan queue:restart` и убедиться, что Supervisor снова показывает `RUNNING`.
4. Открыть в админке раздел Ozon, вкладку `Seller API`.

Полная frontend-сборка нужна только при подготовке версии к развертыванию.

## Первичная настройка

1. В личном кабинете Ozon создать API-ключ с правами на товары, цены, остатки и справочники.
2. В блоке `Подключение` указать `Client-Id` и API-ключ. Ключ хранится в базе в зашифрованном виде и повторно в интерфейс не возвращается.
3. Для FBS или rFBS указать `Warehouse ID`. Для FBO остатки передает сам Ozon.
4. Нажать `Сохранить`, затем `Проверить подключение`.

## Сопоставление категорий

1. Выбрать категорию магазина.
2. Найти категорию и тип Ozon или ввести их ID вручную.
3. Нажать `Настроить атрибуты`.
4. Для обязательных атрибутов выбрать источник:
   - `Поле товара`: например `name`, `sku`, `description`;
   - `Поле вариации`: например `name`, `sku`;
   - `Постоянное значение`: одно значение для всей категории.
5. Для словарного атрибута нажать `Значения Ozon` и выбрать допустимое значение. Система сохранит не только текст, но и ID словаря Ozon.
6. Сохранить сопоставление.

Справочники Ozon кэшируются на 12 часов. Кнопка обновления очищает кэш и принудительно получает актуальный справочник; обычное открытие страницы лимит API не расходует.

## Проверка и отправка

1. Ввести ID товаров через запятую.
2. Нажать `Проверить товары`. Для каждой вариации формируется отдельный `offer_id` и показываются локальные ошибки.
3. Сначала отправить `Карточки`. Ozon обрабатывает импорт асинхронно, поэтому статус некоторое время будет `awaiting_result`.
4. После успешной публикации отправить `Цены` и `Остатки`.

Если оставить список ID пустым, после подтверждения будут обработаны все активные товары. Отправка выполняется пакетами не более 100 позиций через Laravel Queue.

## Формирование данных

- Товар с активными вариациями отправляется как отдельная позиция Ozon для каждой вариации.
- `offer_id`: SKU вариации, затем служебный ID вариации; для товара без вариаций используется SKU товара или служебный ID товара.
- Цена: корректная акционная цена, если она больше нуля и меньше основной, иначе основная цена.
- Габариты магазина считаются сантиметрами и передаются Ozon в миллиметрах.
- Вес магазина считается килограммами и передается Ozon в граммах.
- В первую очередь используются упаковочные вес и габариты, затем обычные данные вариации, затем товара.
- Для вариации сначала используются ее изображения, а при их отсутствии изображения товара.

## Журнал и ошибки

Каждый запуск хранит режим, количество позиций, успешные и ошибочные позиции. Для каждой позиции сохраняются отправленный payload, ответ Ozon и ошибки. API-ключ в журнал не записывается.

Основные причины отказа:

- отсутствует сопоставление категории;
- не заполнен обязательный атрибут или словарное значение;
- цена равна нулю;
- отсутствуют реальные вес или габариты;
- нет изображения;
- для синхронизации FBS-остатков не указан `Warehouse ID`.

Цена и остаток синхронизируются отдельно от карточки. Поэтому уже опубликованный товар можно обновить по цене или остатку даже при временной проблеме с изображением или атрибутами карточки.

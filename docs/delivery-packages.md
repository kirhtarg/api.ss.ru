# Грузовые места и расчет доставки

## Единая модель

Все калькуляторы и создание отправлений используют `DeliveryPackageService` и один массив грузовых мест.

Приоритет веса и габаритов:

1. Транспортные поля вариации (`shipping_*`).
2. Транспортные поля основного товара.
3. Транспортные поля, переданные клиентом.
4. Обычные физические поля вариации.
5. Обычные физические поля товара.
6. Поля запроса клиента.
7. Значения по умолчанию в настройках перевозчика.

Для нового заказа создается расчетный снимок упаковки. Обычные позиции объединяются в одно оценочное место по суммарному объему и максимальным сторонам. Единицы товаров с флагом `Отправлять отдельным местом` остаются отдельными местами. Это воспроизводимая предварительная оценка, а не замена фактической упаковки.

После фактической упаковки менеджер открывает `Упаковка` в строке заказа, указывает реальные коробки и нажимает `Подтвердить упаковку`. Подтвержденные места получают приоритет во всех интеграциях.

В заказах СДЭК эта же кнопка называется `Упаковка и вес` и находится непосредственно в модалке создания отправления. Над составом заказа выводятся число мест, физический, объемный и тарифицируемый вес. Два товара могут быть объединены в одно место: число позиций заказа и число коробок не обязаны совпадать.

## Объемный вес

Интерфейс показывает:

- физический вес;
- объемный вес: `длина * ширина * высота / 5000`;
- тарифицируемый вес: максимум из физического и объемного.

Физический вес не заменяется объемным в базе. Перевозчик самостоятельно применяет правила тарификации к переданным весу и размерам.

## Передача перевозчикам

### СДЭК

В `packages` передается каждое грузовое место с собственными весом и габаритами. Вес переводится из килограммов в граммы.

Первичная загрузка тарифа, `Настроить тариф` и `Пересчитать тариф` в админке используют защищенный расчет для конкретного заказа `GET /api/admin/shop/orders/{id}/cdek/tariffs`. Поэтому они не могут перейти на дефолтную коробку из-за отсутствующего `cart_items`.

Цена позиции СДЭК берется только из сохраненной позиции заказа (`unit_price` / `final_price` / `price` в этом порядке). Присланные браузером `packages.items.cost` и `packages.cost` не имеют приоритета и заново цену не пересчитывают. Это особенно важно для товаров с тегами, отключающими скидку зарегистрированного пользователя.

Стоимость, уже записанная в старом заказе, является исторической суммой для покупателя. Новый запрос тарифа показывает актуальную котировку СДЭК; она может отличаться из-за изменения тарифа перевозчика, наценки, страховки или из-за того, что старый заказ был рассчитан до появления единой модели упаковки.

### Деловые линии

- `quantity`: число мест;
- `weight`: вес самого тяжелого места;
- `totalWeight`: суммарный физический вес;
- `length`, `width`, `height`: максимальные размеры места в метрах;
- `totalVolume`: сумма объемов всех мест.

### Почта России

Расчет выполняется через авторизованный API `1.0/tariff` с габаритами. Упрощенный публичный расчет только по весу больше не используется. Для нескольких мест стоимость считается как сумма отдельных отправлений, а при создании в backlog передается несколько записей.

### Яндекс Доставка

Каждая коробка передается отдельным элементом `places` с отдельным barcode. Товары привязываются к соответствующему месту.

## Изменение данных заказа

Изменение товара после оформления заказа не меняет сохраненный расчетный снимок упаковки. Если состав заказа изменили в админке, нажмите `Сбросить к расчетным`, проверьте новые места и подтвердите упаковку повторно.

## Выкладка

1. Сделать резервную копию БД.
2. Выложить backend-код.
3. До обработки новых заказов выполнить:

   ```bash
   cd /var/www/api.ss.ru
   php artisan migrate --force
   php artisan optimize:clear
   ```

4. Выложить собранный frontend атомарным переключением release-каталога.
5. Проверить новый заказ с двумя единицами товара и заказ с двумя разными товарами.
6. В админке проверить `Упаковка`, затем тестовое создание отправления каждого активного перевозчика.

Откат кода требует сначала прекратить создание новых заказов. Миграцию сразу не откатывать: старый код игнорирует новые таблицу и поля, а их удаление уничтожит сохраненные упаковки.
